# Collection, analysis and reporting development plan

Scope: k957 collection, analysis and reporting capabilities, remaining engineering work and acceptance criteria. k957 0.15.0 remains a developer preview. Current source-bound platform measurements are recorded in [the test report](TEST_REPORT.md).

## Collection

k957 has signed logical collection, resumable acquisition epochs, descriptor metadata, separate SQLite online backup, OS artifact profiles and memory-first full collection. Default full artifact collection now additionally acquires regular files referenced by observed process executable paths. `adaptive-executables.json` binds PID/path observations to later package IDs/hashes and is a signed collection artifact. Linux uses `/proc/<pid>/exe` and executable file-backed `/proc/<pid>/maps` entries; Windows uses `EnumProcesses`/`QueryFullProcessImageName` and Tool Help module snapshots; macOS uses absolute paths from `ps`. Library/module enumeration is a subsequent implementation without a new native runtime check. Explicit custom profiles preserve their selected scope.

The adaptive implementation selects Linux executable mapped files and Windows loaded modules, including libraries/DLLs. It does not select macOS libraries, data-only/unlinked/manual Windows modules, recently opened files or deleted executable bytes. [Method and scope](ADAPTIVE_ACQUISITION.md). Permission failures and exited/deleted processes remain explicit. Its file hash describes later acquired bytes, not a proven memory mapping. Logical acquisition limits still apply; full memory analysis has separate unlimited result storage. Mapped/deleted data requires kernel memory examination and compatible symbols.

Remaining collection work: broader activity-driven dependencies, VSS/filesystem snapshots, complete Windows ADS/SACL/sparse fidelity, physical disk imaging and real platform/device validation. EDR deployment, remote destinations and live provider APIs need concrete transport protocols and authorized target access. Existing disk image examination and offline CloudTrail import do not provide those capabilities.

## Analysis

k957 has source-bound native/text/network projections, exact hash sets, typed event predicates, labelled rule evaluation, source/time-scoped case joins and signed examiner decisions. The new offline IOC list matches exact SHA-256/IP/domain values with list provenance and source/native/packet references. The review queue exposes a deterministic reason for its order. It is not a probabilistic malware score. Observed hashes/IPs and Timesketch JSONL export automatically. Explicit rule `techniques` metadata exports an ATT&CK Navigator layer with candidate counts and source-linked mappings; techniques are never guessed from literal words.

Memory examination now retains every scanned literal match, structured observation, URL token and supported printable string in hashed private JSONL. It has no artificial image size, range count, result count or tool runtime/output ceiling. Installed platform Volatility plugins and global banner/YARA plugins are discovered and attempted, using offline supplied symbols. Advertised boolean dump/thread options are enabled. Successful, failed and unavailable modules remain distinguishable; recovered files and diagnostics are retained and hashed. `/tmp` is preferred when it can hold staging; the output filesystem provides a fallback and an explicit work directory is available. The general case inventory/index capacity does not stop memory result collection.

Remaining analysis work: valid RAM/reference-symbol process/socket comparisons, wider native format/version corpora, MFT, broader USN versions/path reconstruction, Amcache/SRUM/TCC interpretation, transaction-log recovery, compressed Prefetch, binary Linux journal/macOS unified logs, temporal rule sequences, defined Sigma/YARA interchange, validated process relationship reconstruction and malware provider adapters. A byte/header observation or an exact supplied IOC does not establish execution or compromise. Optional providers require their credentials/license and a defined disclosure policy. Current optional tool hashes do not bind all interpreter libraries or establish a complete OS sandbox.

## Reporting

k957 now generates native `report.pdf` by default alongside HTML for package/store analysis, masked sharing, unified cases and selected case records. Both use a restrained examination folio: serif titles, warm paper, dark ink, a single muted accent, numbered sections, source references and visible coverage. The native PDF has embedded fonts, folios, page totals and a source projection/omission receipt. Unsupported glyphs use recorded code-point escapes; original strings remain in HTML/JSON. Shared PDF is generated from the masked projection. HTML print events render all paginated finding/inventory rows and restore the interactive state afterward.

Inventory, acquisition issues, kernel method statuses, examiner decisions, exact IOC matches, activity and timeline are reported within declared reading-edition limits. Complete private memory results remain separate and unbounded. JSON/CSV and the case index remain the examination data. Signing the report bundle covers default PDFs and all included files. DOCX remains an explicit export. See [reporting](REPORTING.md) and [memory](MEMORY.md) for commands, provenance and privacy boundaries.

Remaining reporting work: native Word/renderer corpus, a full accessibility audit, wider font/script coverage, spreadsheet/Autopsy-specific adapters and deeper interactive investigation workflows.

## Development order and acceptance

1. **Implemented: memory completeness and storage.** Remove former 8 GiB external image, two-minute tool, 32 MiB output, 100,000 row and scan count cutoffs. Retain disk-backed results and method-level failures. Acceptance includes a synthetic image larger than 8 GiB, >100,000 output rows, >32 MiB stdout, >64 KiB stderr, unchanged source hashes, reconstructable long strings/URLs and receipt tamper rejection. These test orchestration, not kernel accuracy.
2. **Implemented: default reporting and portable evidence.** Default native PDFs for all report scopes, shared projection privacy, source/coverage receipts, independent PDF text checks, report seal verification/tamper rejection, Timesketch schema, review queue and explicit ATT&CK mapping tests. Visual review covers the native folio and interactive HTML print pagination.
3. **Implemented first scope: adaptive acquisition and offline indicators.** Process executable references and signed acquisition linkage; exact offline IOC normalization and original row/packet references. Acceptance uses synthetic process references and independent SQLite browser records. Windows/macOS discovery requires native positive/error-path runs before platform accuracy claims.
4. **Next engineering scope: native evidence breadth.** Add one documented format at a time, with independent reference fixtures, raw record/time/offset provenance, malformed/version tests and explicit unsupported outcomes. Prioritize MFT, USN v4/path reconstruction and reference acceptance, Amcache/SRUM, Registry logs and native system logs. Do not advertise collected-but-unparsed artifacts as analyzed.
5. **Next engineering scope: detection and investigation.** Define temporal/Sigma/YARA semantics, process relationship provenance, labelled production rule corpora and examiner interaction. Keep candidate counts, manual confirmation, provider verdicts and confidence measurements separate.
6. **Service and integration scope: licensed providers, EDR and teams.** Implement a named provider/transport after specifying authentication, permitted evidence transfer, retries, custody, revocation and audit retention. Multi-user case services need roles, transactions and conflict handling. Cross compilation is not acceptance for these workflows.
7. **Required external assurance.** Native Windows/macOS/ARM hosts, valid RAM plus exact symbols, physical devices and selected provider access. Current tests cannot replace these resources.
